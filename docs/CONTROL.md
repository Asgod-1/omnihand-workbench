# 十轴位置控制与网页动作

2026-11-18更新。适用于当前O10触觉右手，复用正在运行的工作台连接。模型始终显示设备反馈；开启控制并使能后，滑块直接发送对应轴目标。

## 网页使用

打开本地工作台 <http://127.0.0.1:8765/>。三维面板内可选择并发送预设。宽屏并排显示三维、七区触觉和单轴滑块，窄屏将滑块放到观测区下方。“停止并保持”位于顶栏。

1. 点一个预设，仅选择目标数值；点击发送才执行。三维和触觉持续显示设备反馈，不再显示目标姿态，也没有展开示意。
2. 点“开启控制”，软件回读位置、诊断及CAN电机状态后解除本会话的控制锁。这一步不发送电机写指令，也不自动使能。
3. CAN FD连接若显示未使能，可点“电机使能”。程序先预置当前姿态，再发送使能并回读确认；如果已使能则不重复写入。官方Python USB接口未提供使能方法，USB模式只提供位置控制，需设备预先处于使能状态。
4. 右手位置控制默认使用“分段切换”。它适用于空手换手势。也可选择“直接发送”一次下发完整十轴目标，或用“电脑渐变”设置插值时长。
5. “停止并保持”优先取消旧队列及后续位置目标，再读取当前位置并发送保持目标。只有匹配应答后才显示保持已确认。“锁定控制”在动作中也会取消并请求保持，空闲时仅上锁。

若下发应答失败导致软件重新锁定，本会话的“停止并保持”仍可手动再次请求；不会自动重发失败动作。通信未恢复时，保持请求也可能失败，应查看错误提示与硬件状态。

“失能·释放保持力”会发送电机失能并重新锁定软件控制；电机不再保持，抓持物可能松开。软件停止依赖通信，不能替代硬件急停。关闭浏览器不会取消后台已启动的动作，也不会断电。执行中断开工作台连接时，后端先请求停止保持，确认后才关闭通信；空闲断开不切换电机电源。

开启控制并使能后，拖动滑块即可发送所选轴目标。数值输入在回车或结束编辑时发送。每轴绿色数字独立显示反馈。快速拖动时只保留每轴最新值，最多一个请求在途，常规最短发送间隔为45 ms。CAN FD 单轴位置保留逐次应答和故障复核，位置由采样线程连续回读。停止、锁定、失能、选预设及重连会清除未发送值。

目标严格要求0–4096整数，原始反馈越界值仍保留；同步反馈时只对新的目标限幅。数值目标与反馈分开显示，可将当前目标保存成预设。网页默认不自动解除控制锁或使能。

## 官方支持的控制组合

官方[O10 Python文档](https://github.com/AgibotTech/agilink_omnihand_sdk/blob/main/doc/en/API_PYTHON_O10.md)与本地SDK1.1.11提供：

| 组合 | Python调用 | 本项目参数 |
| --- | --- | --- |
| 位置 | `set_all_joint_positions` / `set_joint_position` | 十轴位置或单轴位置，0–4096 |
| 位置＋电流PT | `mix_control_by_pt` | 位置与十轴`currents_ma`，0–1000mA |
| 位置＋速度＋电流PVT | `mix_control_by_pvt` | 再加十轴`velocities`，当前适配为-4095–4096原始值 |

O10不支持通过`set_control_mode`切换成纯力矩或独立速度控制；读取速度不是独立速度控制。SDK中名为torque的参数实际是电机电流mA，不是N·m，也不是指尖牛顿力。本项目不发送保护电流阈值设置；官方说明该类设置不能与混合控制并用。

网页电流和速度输入统一应用到各轴，Python可分别指定十个值。CAN FD与演示支持单轴混合。当前USB私有协议提供整手混合，单轴滑块使用位置组合。选择组合后，下一次发送采用所选组合。混合组合使用直接发送。

CAN混合使用SDK实测公有`0x0014..81`编码，公有手ID读取配置`raw_public_hand_id`；电流编码按SDK的`floor(mA*255/1000)`。PT全手一帧，PVT为9＋1轴两帧，不能视作十轴原子同步。新路径只确认传输提交、独立0x0D故障读取和实际位置反馈，**没有将反馈查询冒充混合指令ACK或模式确认**；日志标为`mixed_target_submitted`与`transport_submitted_with_readback`。本轮未验证实机混合动作或电流效果，不能据此宣称完成力控标定。

自定义动作保存在Git忽略的`data/actions.local.json`，同名动作不会被静默覆盖。所有控制日志保存在`data/motion_*.jsonl`，记录模式、请求、位置目标、应答、故障和完成状态。

## 分段切换

整手一次接收最终位置时，各轴按自身速度运动，容易在中途发生指间干涉。分段切换从当前实测位置出发，先伸直拇指，再张开四指，然后调整拇指方向和手指侧摆。四指先进入目标，最后收拢拇指。已在到位范围内的中间步骤会跳过。每段直接发送一次目标，两次新鲜位置反馈到位后才准备下一段，并在发送前复核上一姿态和设备状态。

单段等待超时会取消剩余步骤并请求保持当前位置。网页显示当前阶段，可以随时点击顶栏“停止并保持”。这套顺序按右手张开预设设计，目前已做模拟验证，实际擦碰和空手切换效果待实机验证。

演示模式生成连续位置反馈，浏览器在相邻反馈间补帧。握拳2、OK 和数字1至4的演示目标微调了拇指位置。用官方 STL 网格和 1 毫米体素抽样检查了 306 个预设分段切换，采样姿态未检出指间交叠。实机接口使用官方预设位置。

## Python开发入口

先启动工作台；Python客户端通过本机HTTP调用它，**不另开SDK、串口或达妙模块**，与网页共享同一动作队列。

默认只预览，不运动：

```powershell
.\.venv\Scripts\python.exe examples/08_position_control.py --preset open
```

以下命令会实际发送位置目标；`--enable-motors`还会在必要时使能电机：

```powershell
.\.venv\Scripts\python.exe examples/08_position_control.py --preset open --execute --enable-motors
```

可以从自己的Python程序调用：

```python
from omnihand_usb.control_client import ControlClient

hand = ControlClient()  # 默认127.0.0.1:8765；构造时不连接硬件
print(hand.catalog()['presets'])
preview = hand.preview(preset='open')  # 只有目标与运动学计算

# 以下代码由开发者明确调用后才控制设备。
hand.arm()             # 回读检查并开启软件控制
try:
    hand.enable()      # CAN FD可用；USB模式省略并预先确认已使能
    started = hand.move(preset='three', mode='staged')  # 右手分段切换
    hand.wait(started['motion_id'])
    # 可选电脑插值：hand.move(preset='open', mode='smooth', duration=6)
    # 也可以手动hand.stop()，或hand.move(positions=[...10个整数...])
finally:
    hand.lock()        # 正在执行时请求停止保持；不失能、不切断电源
```

客户端不会在重连后自动重新开启控制。旧`session_id`的控制请求被拒绝；需明确调用`arm()`取得新会话。`wait()`超时不重发动作，应查看反馈或明确调用`stop()`。独立示例退出时在`finally`中锁定控制。

## 实现与当前范围

CAN FD使用原配节点的标准FD+BRS帧：`0x08 + 10个小端uint16目标`，21个有效字节填充到合法24字节DLC；应答为命令字+60字节反馈。FW1.2.14实测中，旧手册所称的末10字节“轴故障”会在独立错误码为0时非零，因此现保留为`ack_status_raw`，不直接解释为故障；每个位置应答后都查询官方独立`0x0D`整手错误码，非零或查询失败仍停止下发并锁定。日志保留完整`response_hex`供后续核对。

`0x01 + 0/1`设置使能/失能，`0x02`回读状态。命令依据本地官方O10手册及v1.1.11 `private_omnihand.h`；手册0x08表中另有“预留自由度”描述与20字节定义不一致，当前按头文件十轴20字节定义实现。未发送校准值2，也不提供任意CAN帧或持续参数写入接口。

USB位置调用官方SDK的`set_all_joint_positions`/`set_joint_position`，整手混合调用`mix_control_by_pt`/`mix_control_by_pvt`。当前没有纯力矩或触觉抓取闭环。

默认`direct`方式在状态检查后一次发送完整十轴目标，不使用电脑的80计数步长或渐变时长。收到应答后只读取反馈，不重复下发该目标；单次协议报文并不表示手瞬间到位，实际速度、轨迹与限值由设备内控制器决定。本接口未修改设备速度、力或力矩参数。

可选`smooth`方式保留原有电脑插值：100ms最小下发间隔，每轴每步最多80个编码值，名义目标变化速率上限800计数/秒，完整范围渐变至少7.68秒。选定时长太短会自动延长，查询延迟也会延长实际时间。这些只限制电脑发送的中间目标，不能代表电机固件的保护设定。

HTTP 整手请求 `POST /api/control` 使用 `action:"move"`。发送方式 `execution_mode` 可选 `direct`（接口默认）、`smooth` 或 `staged`。渐变方式接受 `duration`，分段状态提供 `stage.index`、`stage.total`、`stage.name`。单轴请求使用 `action:"joint"`、从 1 开始的 `index` 与 `position`。PT 请求带 `currents_ma`，PVT 再带 `velocities`。Python 对应 `hand.joint(5,1200)` 与 `hand.move(positions=targets, control_mode='pvt', currents_ma=[100]*10, velocities=[500]*10)`。

所有设备读写由同一采集线程执行，并在各区域读取之间检查停止请求。已经提交的 USB/CAN 调用结束后才会处理停止。应答丢失或故障后锁定控制。到位要有两次新鲜位置回读。分段过渡姿态的误差上限为 40。CAN FD 位置控制的最终目标使用 64 个位置单位的到位阈值，并显示最大偏差。实测位置停滞且仍超出到位范围时，位置控制提前保持并报告偏差。直接发送与分段切换的每段等待上限为 10 秒，电脑渐变结束后上限为 3 秒。
