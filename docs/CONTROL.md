# 十轴位置控制与网页动作

2026-11-18新增。适用于当前O10触觉右手，复用正在运行的工作台连接。启动、连接、刷新、预览和滑块编辑均不发送电机写指令。

## 网页使用

打开本地工作台 <http://127.0.0.1:8765/>，在“动作工作台”操作：

1. 点一个预设，三维显示“动作预览·尚未下发”。此时二维触觉继续采集，三维触点暂隐藏，避免把目标姿态误当作实测接触位置。“显示实测”可随时恢复。
2. 点“开启控制”，软件回读位置、诊断及CAN电机状态后解除本会话的控制锁。这一步不发送电机写指令，也不自动使能。
3. CAN FD连接若显示未使能，可点“电机使能”。程序先预置当前姿态，再发送使能并回读确认；如果已使能则不重复写入。官方Python USB接口未提供使能方法，USB模式只提供位置控制，需设备预先处于使能状态。
4. 选择渐变时长，点“执行目标”才开始下发。网页恢复显示实际位置，状态显示进度、有效渐变时长及动作日志路径。
5. “停止并保持”优先取消旧队列及后续位置目标，再读取当前位置并发送保持目标。只有匹配应答后才显示保持已确认。“锁定控制”在动作中也会取消并请求保持，空闲时仅上锁。

若下发应答失败导致软件重新锁定，本会话的“停止并保持”仍可手动再次请求；不会自动重发失败动作。通信未恢复时，保持请求也可能失败，应查看错误提示与硬件状态。

“失能·释放保持力”会发送电机失能并重新锁定软件控制；电机不再保持，抓持物可能松开。软件停止依赖通信，不能替代硬件急停。关闭浏览器不会取消后台已启动的动作，也不会断电。执行中断开工作台连接时，后端先请求停止保持，确认后才关闭通信；空闲断开不切换电机电源。

展开“自定义十轴目标与保存”，可取当前姿态、编辑十轴目标、预览后执行，或命名保存成预设。目标严格要求10个0–4096整数，原始反馈越界值仍保留；“取当前姿态”仅对新目标限幅。未先取姿态或选预设时不启用滑块，避免把未编辑的其他轴默认为零。

自定义动作保存在Git忽略的`data/actions.local.json`，同名动作不会被静默覆盖。所有控制日志保存在`data/motion_*.jsonl`，记录模式、请求、位置目标、应答、故障和完成状态。

## 预设及来源

| ID | 名称 | 来源 |
| --- | --- | --- |
| open | 张开手 | 官方SDK PAPER |
| half_grip | 半握 | 张开与握拳1的十轴位置中点 |
| fist1 / fist2 | 握拳1 / 握拳2 | 官方SDK FIST1 / FIST2 |
| ok | OK | 官方SDK OK |
| like | 点赞 | 官方SDK LIKE |
| one / two | 数字1 / 数字2、V | 官方SDK NUM1 / NUM2 |
| heart | 单手比心 | 官方SDK oneheart |

共九个预设。半握是位置插值，**不代表50%抓力**。以上官方八种手势的十轴目标从未经修改的`omnihand==1.1.11`离线采集：SDK连接本机TCP模拟器，调用`set_hand_gesture`，截取其`0x00130181`十轴位置帧，未转发至实机。采集文件SHA-256为`3fe1e136fcba51e50066fe3451544090b9289a59291b7d38c45395a13a04355a`，数据固化在`src/omnihand_usb/presets.json`；本机原始记录在`data/control-gesture-sdk-capture.json`。

这些目标仅标记为右手，左手连接不会套用；实际动作和接触结果仍需按实机、固件与安装姿态验证。

## Python开发入口

先启动工作台；Python客户端通过本机HTTP调用它，**不另开SDK、串口或达妙模块**，与网页共享同一动作队列。

默认只预览，不运动：

```powershell
.\.venv\Scripts\python.exe examples/08_position_control.py --preset open
```

以下命令会实际发送位置目标；`--enable-motors`还会在必要时使能电机：

```powershell
.\.venv\Scripts\python.exe examples/08_position_control.py --preset open --duration 6 --execute --enable-motors
```

可以从自己的Python程序调用：

```python
from omnihand_usb.control_client import ControlClient

hand = ControlClient()  # 默认127.0.0.1:8765；构造时不连接硬件
print(hand.catalog()['presets'])
preview = hand.preview(preset='open')  # 只有目标与运动学计算

# 以下代码由开发者明确调用后才控制设备。
hand.arm()             # 回读检查并开启软件控制
try:
    hand.enable()      # CAN FD可用；USB模式省略并预先确认已使能
    started = hand.move(preset='open', duration=6)
    hand.wait(started['motion_id'])
    # 也可以手动hand.stop()，或hand.move(positions=[...10个整数...])
finally:
    hand.lock()        # 正在执行时请求停止保持；不失能、不切断电源
```

客户端不会在重连后自动重新开启控制。旧`session_id`的控制请求被拒绝；需明确调用`arm()`取得新会话。`wait()`超时不重发动作，应查看反馈或明确调用`stop()`。独立示例退出时在`finally`中锁定控制。

## 实现与当前范围

CAN FD使用原配节点的标准FD+BRS帧：`0x08 + 10个小端uint16目标`，21个有效字节填充到合法24字节DLC；应答为命令字+60字节反馈（10轴位置、速度原始值、力矩原始字节、故障）。`0x01 + 0/1`设置使能/失能，`0x02`回读状态。命令与字段依据本地官方O10手册及v1.1.11 `private_omnihand.h`；手册0x08表中另有“预留自由度”描述与20字节定义不一致，当前按头文件十轴20字节定义实现。未发送校准值2，也不提供任意CAN帧或持续参数写入接口。

USB调用官方SDK的`set_all_joint_positions`。这版只提供位置控制，尚未加入纯力矩、力位混合或基于触觉的抓取闭环。

主机以100ms最小间隔进行平滑位置渐变；每轴每次最多改变80个编码值，名义目标变化速率上限800计数/秒，完整范围渐变至少7.68秒。选定时长太短会自动延长；查询延迟也会延长实际时间。这是**主机目标变化限制**，不是电机固件的速度、力或碰撞保护设定。

所有设备读写由同一采集线程排队执行，并在各区域读取之间检查停止请求。停止无法中断已经提交、正在等待应答的USB/CAN调用，因此没有硬实时停止时延保证。应答丢失或故障后停止后续下发并重新锁定，不自动重发不确定的动作。到达目标后还需两次位置反馈的每轴误差≤40才算完成；等待超过3秒未到位会请求保持当前位置并报告未到位。这不等于抓持力验证。
