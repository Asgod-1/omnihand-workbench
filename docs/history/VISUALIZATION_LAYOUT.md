- 相机中心取当前关节姿态的模型包围盒中心；首次有效反馈、窗口尺寸变化和“居中”按钮都会重新适配。按视口宽高比计算距离，避免只按模型零位或固定距离取景。
- 掌面/手背采用约 680 ms 的平滑球面轨道切换，保留缩放距离；拖动可以打断动画。仅改变视角。
- 页面取消固定最大宽度，避免宽屏右侧留白。位置曲线移到关节表右侧，下方放采集信息和记录卡。

## 更细的触觉查看

默认显示真实可用的普通触觉，原始阵列状态始终在标签上可见。选择任意区域可查看各点索引、当前值、峰值、峰值索引、均值、非零点数和更新时间。触点支持悬停、点击和键盘选择；可以放大图形、显示/隐藏数值，以及切换统一自动色阶或固定 0–255。

点击触点会固定当前索引，切换排布后仍查看同一个实测点；点击“已固定 · 解除”恢复跟随指针。放大或切换排布不会改变底层数据。

三维部位选择与触觉区域互相联动。三维仍按区域峰值着色，没有把未知坐标的触点贴到任意模型位置。显示比例不会改变真实测量分辨率。

## 官方相对排布与物理尺寸的边界

已从固定 SDK 1.1.11 的[官方 O10 C++ 文档](https://github.com/AgibotTech/agillink_omnihand_sdk/blob/v1.1.11/doc/en/API_CPP_O10.md)找到 16 点手指索引图：

- 右手为 2 列 × 8 行，上方 `[14,15]`，下方 `[0,1]`；左手列方向相反。
- 图片不提供毫米坐标、触点长宽和曲面投影。
- 同一 SDK 的 `private_omnihand.h` 又把普通手指数据注释为 4×4，与图片存在出入。因此目前只能称“官方相对索引图”，不能声称已经确认当前私有协议各点的实际位置。需要逐点接触核验，或由智元提供这只 T1 手的索引映射。
- 手心/手背以及 18 点原始手指没有查到完整、可核实的物理坐标。本项目明确使用“索引排列 · 非物理坐标”，不自动套用 16 点图，也不推测毫米尺寸。

官方图片放在 Git 忽略的 `vendor/web_assets/tactile/`；网页可点击“查看官方索引图”。下载地址和 SHA-256 固定在资源重建脚本中。映射逻辑集中于 `src/omnihand_usb/web/tactile-layout.js`，后续拿到厂商点位表可替换为真实坐标与触点尺寸。
