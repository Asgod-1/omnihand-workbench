# 原始触觉与整手三维

2026-11-18界面更新：原始与普通七区全部展开，不再需要标签或区域切换。二维按官方上位机点序绘制，三维使用独立逐触点表面投影。新界面的来源、校准边界与操作见 [TACTILE_SURFACE_MAPPING.md](../TACTILE_SURFACE_MAPPING.md)。

2026-11-17 最新实测：手 **FW1.2.14**、达妙双路板 **dual_app v1.0.0.7**，七区域 **268 点**连续读取通过两轮 **20/20 组**验证，软件重连正常、采集错误 0。每组完整返回 5 个分包；普通 130 点和 10 轴位置并行正常。本机原始采集开关已开启。完整证据与短时测试的边界见 [RAW_TACTILE_DIAGNOSIS.md](RAW_TACTILE_DIAGNOSIS.md)。

历史对照（2026-11-16，FW1.1.9）：整手三维和普通触觉已通过实机验证，当时原始阵列未返回。以下故障历史不能代替升级后的最新结果。

## 使用

双击项目根目录 `Start_CANFD_Dashboard.cmd`，打开 http://127.0.0.1:8765/ 。当前使用达妙双路物理 CAN1、手节点 `0x09`、仲裁域 1M/80%、数据域 5M/75%。

网页直接显示全部268点，包括手背102点的官方不规则排布及单点数值。运行中的网页也可被自己的Python程序读取，无需另开设备连接：

```powershell
.\.venv\Scripts\python.exe examples/07_read_raw_from_dashboard.py
```

该示例只读取本地 `/api/state`，校验完整的七区域长度后输出 `regions[区域].values`。这是本项目的 HTTP 接口；直接使用硬件时由 `DamiaoHand.raw_tactile()` 读取。

- “整手三维”使用智元官方 2026-08-27 右手 URDF/STL，包含 18 个部件。拖动旋转、滚轮缩放；“掌面/手背”、线框和部件选择均只影响显示。
- 姿态来自实际读到的 10 轴位置，调用本机官方 `omnihand==1.1.11` 的 `actuator_input_to_active_joint_pos()` 和 `get_all_joint_angles()` 解算。16 个活动关节中，6 个被动关节角度为计算值，不是独立测量值；URDF 中中指侧摆固定为零。
- 位置轻微超过 4096 时，原始数据完整保留，仅求解器输入限幅，网页显示限幅轴号。
- “原始阵列/普通触觉”是两个数据来源。原始未返回时显示空状态，不把 130 点普通数据、插值结果或补零数组当作原始数据。
- 三维每个色点表示同一索引的独立读数，使用官方二维点序和模型表面配准。逐点毫米坐标仍需按压校核，不能把注册范围或显示圆点大小当作厂家实测尺寸。
- “导出快照”下载 JSON，包含位置、关节角、普通触觉、原始接口状态和时间戳。“开始记录”保存同样字段的连续 JSONL 到 `data/`。原始字段应检查 `status == "ready"`，不能只看存在 `expected_counts`。

## 升级前的阻塞与处理（FW1.1.9 历史）

升级前实机：O10 T1、硬件 3.0.0、设备固件 **1.1.9**；当前已升级为 **1.2.14**。设备固件与 PC 上 SDK 1.1.11 不是同一件事。普通查询使用标准 CAN FD 帧，节点 `0x09`，已正常返回位置和 130 点普通触觉。

官方 `OmniHand2025CanImpl` 的原始读取走公有扩展 CAN FD 协议。离线模拟器核对了未修改官方 SDK 的确切输出：

- `get_num_of_tactile_sensors()`：扩展 ID `0x00060101`，1 字节 `01`。
- `get_all_tactile_sensor_data_raw()`：扩展 ID `0x00060101`，64 个零字节，FD+BRS 数据帧。
- `get_tactile_sensor_data_raw(Finger.THUMB)`：扩展 ID `0x01060101`，64 个零字节。
- SDK 1.1.8（与已安装 ToolBox 2.7.2 的 omnihand.dll 完全一致）和 1.1.11 输出的批量原始请求相同。
- 以上 ID 已由当前手的官方广播回复确认，不再使用早先误代入的私有节点 9。没有扫描未知地址。

升级前实机未返回上述公有接口的原始阵列。后一次桥接测试还出现适配器发送/通道配置失败；软件 USB 复位未恢复，用户重新插拔达妙模块 USB 后恢复普通采集。当时关闭了自动原始探测。此段为故障历史，当前开关已开启，兼容性记录已更新为实际成功结果。

这些结果不能直接证明该硬件没有原始触觉，也不能直接断定换某个固件就能解决。需要智元确认：

1. O10 T1 / HW3.0.0 / FW1.1.9 是否支持公有 CAN 原始触觉接口？已实测确认公有手 ID 1、私有节点 9，基础公有查询正常。
2. 如果该交付版本使用私有标准帧协议，是否另有完整原始触觉阵列的只读命令、分包规则、触点索引/坐标图？
3. 如果需要升级，提供适配该硬件与触觉 SKU 的固件、版本要求和升级说明。官网列出的通用固件不能据此直接刷入。

当前生产路径由达妙模块收发，项目直接重组原始五分包，解码结果已与官方 SDK 1.1.11 对真实捕获的 268 个值逐点比较一致；无需额外厂商解码进程。原始 GET 使用扩展 ID `0x00060101`、一字节显式 `00`、FD+BRS。只有完整七区域、长度与已验证规格一致的数据才标为 `ready`；丢包不补零，不混用旧帧。旧的官方 SDK 本机桥接仅作为对照保留。

## 模型资源与重建

新电脑先按 README 重建 Python/SDK，再运行：

```powershell
.\.venv\Scripts\python.exe scripts/setup_visualization.py
```

脚本下载并校验官方右手 ZIP 和固定 Three.js 0.170.0，提取到 `vendor/web_assets/`。也可用 `--archive 官方右手ZIP路径` 复用已下载的模型。模型和第三方 JS 均在本机缓存，不提交到 Git；网页运行时不依赖外部 CDN。

HTTP 只允许读取指定的模型/JS 文件，不能通过 `/assets/` 访问驱动 DLL、本机配置或采集日志。服务只监听 `127.0.0.1`，没有动作、使能、校准、刷写接口。
